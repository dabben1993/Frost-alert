Walkthrough for humans

A warning before the temperature drops — not an app, not a service.

You need enough lead time to move outdoor bonsai. The laptop can be off. A friend should be able to clone the repo, set their own place, and run the same thing.

  • One location per clone. No accounts. No custody of anyone else's keys.
  • Alerts arrive in Telegram. You press plants in or plants out — including several times in one autumn.
  • GitHub Actions runs the check. healthchecks.io warns you if that check never reports in.

Coding agents implement from the architecture spine. This deck is the picture, not the contract.

Everything that talks to everything else

One scheduled job in GitHub. Your phone only talks to Telegram. Setup happens once, on your machine.

Default-branch schedule. Public repo on GitHub Free, or Pro if you keep it private. No home server.

Two seasons. You flip them.

The automation never guesses that the trees are safe. Silence means you pressed the button.

Monitoring — plants are out

Each tick looks at the forecast. If a crossing is coming, you get 24h, then 12h, then 6h — once each per local date. A cold week keeps warning until you confirm they are in.

Suspended — plants are in

The job still runs so the watchdog stays honest. No frost alerts. /out or the “plants are out again” button starts monitoring. Same-day resume can warn again.

Telegram only: /in and /out, or the two buttons. The setup CLI is for location and threshold, not this flip. Not a “snooze tonight.”

Any upcoming hour at or below your threshold

Not “nights only.” A daytime drop still counts. Not the live thermometer — that is too late to move trees.

  • Look about 30 hours ahead. Remaining time to the first cold hour picks the step: more than 12h → 24h warning; more than 6h → 12h; otherwise 6h.
  • That first hour’s local calendar date is one frost event. A same-day forecast change does not restart the sequence.
  • Tomorrow is a new event if you have not pressed “plants in.”
  • All temperatures on disk are Celsius. Fahrenheit is a display choice at setup.

Default threshold is 3°C — forecast error and pot soil run colder than the official air number.

One workflow, every six hours, one writer

GitHub can start the next tick before the last one finished. The newer run cancels the older. You can also fire a tick by hand after you press a button.

  • If plants are already in, skip the forecast. Still poll, save, and ping.
  • If both weather APIs fail, do not ping — that miss is the warning that the check failed.
  • If Telegram fails to send, still ping. A quiet phone is not a dead job.

GitHub will be late. The design assumes that.

Free schedulers have no promise you can take to a frost night. Measured delay has been hours, not minutes. A late run still has to be useful.

Windows follow the forecast clock

We do not have a “24h workflow” and a “6h workflow.” The same job asks: how long until the crossing, now?

The watchdog is the miss detector

healthchecks.io: expect a ping every 6 hours, wait about 6 more. If the ping never comes, you get a separate warning — not a frost alert.

Whitelist Telegram from Android battery optimization or the message can sit in a queue while the night arrives.

One forecast. A spare if the first is down.

Open-Meteo is first (no key). If it times out, 500s, or returns garbage hours, MET Norway answers. We never average the two — fallback is “the shop is closed,” not a second opinion.

  • Bad coordinates are not an outage. Fix setup; do not ask Oslo to guess.
  • MET Norway needs elevation and an identifying User-Agent. Missing either gives wrong temperatures or a 403.
  • Setup geocodes once from a city or postal code. The schedule never geocodes again.

Files you can see. Secrets you cannot.

config/user.json

Place, coordinates, elevation, timezone, threshold, °C/°F. Written by setup. You commit it. Not secret.

data/state.json

In or out, which date we are warning about, which steps already sent, and how far we have read Telegram. The job commits this. Not secret.

GitHub Secrets only: bot token, chat id, watchdog ping URL. Python 3.13, uv, stdlib HTTP — no web framework to maintain.

Code shape for builders: domain in the middle, adapters at the edges. Friends who only want it running can ignore that.

Left out on purpose

  • Exact alert wording — preview must be obvious on the lock screen; the opened chat holds the facts. Sentences are not locked.
  • ntfy, email, Pushover — possible later. Telegram is enough for v1.
  • A Sweden-only weather model. Accuracy is the threshold you tune, not a Nordic pin.
  • AWS as the host. Documented as a paid fallback, not built.
