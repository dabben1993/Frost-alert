# Candidate Digest: SMHI Open Data API (Weather Forecast)

Researched for: personal frost-alert automation (checks overnight low temps for a Sweden location).
Accessed: 2026-09-12.

## Claims

- SMHI's current meteorological forecast API is **SNOW1gv1**; it replaced the older **PMP3gv2** API, which was fully decommissioned on 2026-03-31 after a transition period (new API launched autumn 2025, announced 2025-09-12) — source: SMHI Open Data updates, "API för PMP3 avvecklas 31 mars", https://www.smhi.se/data/om-smhis-data/uppdateringar-oppna-data/uppdateringar-i-smhis-oppna-data/2026-03-16-api-for-pmp3-avvecklas-31-mars, published: 2026-03-16, accessed: 2026-09-12, confidence: high, class: reliability
- The PMP3gv2 shutdown broke multiple real-world integrations that had hardcoded the old endpoint (HTTP 404 / decode errors after 2026-03-31), including the MagicMirror dashboard project and the Home Assistant SMHI integration — source: GitHub, "SMHI weather provider broken — PMP3gv2 API returns 404 since March 31, 2026" (MagicMirrorOrg/MagicMirror#4081), https://github.com/MagicMirrorOrg/MagicMirror/issues/4081; corroborated by GitHub, "SMHI integration failing: Provider deprecated pmp3g API on March 31, 2026" (home-assistant/core#166935), https://github.com/home-assistant/core/issues/166935, published: 2026-03-31, accessed: 2026-09-12, confidence: high, class: reliability
- SMHI's open data (including forecast data) requires **no login and no API key**; the point-forecast endpoint is a plain GET, e.g. `https://opendata-download-metfcst.smhi.se/api/category/snow1g/version/1/geotype/point/lon/{lon}/lat/{lat}/data.json` — source: GitHub issue MagicMirrorOrg/MagicMirror#4081 (working curl example) and thejoltjoker/smhi-snow README, https://github.com/thejoltjoker/smhi-snow/, undated, accessed: 2026-09-12, confidence: high, class: integration
- SMHI does **not publish a universal numeric rate limit** for open data; instead its terms ask users to use only documented APIs, avoid mass/duplicate downloads, cache responses, and note that SMHI "reserves the right to block individual IP addresses or completely disable services in cases of obvious abuse" — source: SMHI, "Villkor för användning av SMHIs öppna data", https://www.smhi.se/data/om-smhis-data/villkor-for-anvandning, undated, accessed: 2026-09-12, confidence: high, class: pricing
- One independent third-party project (a Cloudflare-Workers-based MCP server) chose to self-impose a **30 requests/minute** client-side limit specifically to "respect SMHI API limits" — this is the project's own caution, not a documented SMHI quota — source: GitHub, hniska/smhi-mcp README, https://github.com/hniska/smhi-mcp, undated, accessed: 2026-09-12, confidence: medium, class: pricing
- SMHI open data is licensed under **Creative Commons Attribution 4.0 SE**, permitting commercial use, copying, and derivative works, provided SMHI is credited as source and modifications are noted — source: SMHI, "Villkor för användning av SMHIs öppna data", https://www.smhi.se/data/om-smhis-data/villkor-for-anvandning, undated, accessed: 2026-09-12, confidence: high, class: pricing
- The current SNOW1gv1 forecast covers roughly a **10-day horizon** with **variable time resolution**: hourly steps for hours 0–48, 2-hour steps for hours 49–72, 6-hour steps for hours 73–132, and 12-hour steps beyond that — source: MagicMirror Forum, "Swedish Weather provider SMHI has deprecated their API and replaced it" (code walkthrough of the migration PR), https://forum.magicmirror.builders/topic/20191/swedish-weather-provider-smhi-has-deprecated-their-api-and-replaced-it, undated (2026), accessed: 2026-09-12, confidence: medium, class: coverage
- Corroborating the ~10-day/hourly-near-term horizon independently: a community MCP server built directly on SNOW1gv1 advertises a "get_hourly_forecast" tool for the next 1–48 hours and a "get_forecast"/"get_daily_summary" for up to ~10 days — source: GitHub, LittleAndi/smhi-mcp-server README, https://github.com/LittleAndi/smhi-mcp-server, undated, accessed: 2026-09-12, confidence: medium, class: coverage
- SNOW1gv1 responses are JSON with a flat `data` object per time-series entry (e.g. `data.air_temperature`), using key `time` for the timestamp and a `9999` sentinel value for missing data (which client libraries normalize to `null`) — source: GitHub issue MagicMirrorOrg/MagicMirror#4081 and thejoltjoker/smhi-snow README, https://github.com/thejoltjoker/smhi-snow/, undated, accessed: 2026-09-12, confidence: high, class: integration
- The forecast endpoint takes **latitude/longitude only** (WGS84 decimal degrees in the URL path); no place-name or postal-code lookup is offered by the forecast API itself — source: GitHub, thejoltjoker/smhi-snow README (point-forecast signature `getPointForecast(longitude, latitude, ...)`) and MagicMirrorOrg/MagicMirror#4081 curl examples, accessed: 2026-09-12, confidence: high, class: integration
- SMHI publishes **no official SDK**; all client libraries found (Go: osm/smhi; TypeScript: thejoltjoker/smhi-snow; Python-based Home Assistant integration "pysmhi"; multiple MCP servers: hniska/smhi-mcp, LittleAndi/smhi-mcp-server) are community-maintained, and at least two of them (thejoltjoker/smhi-snow, LittleAndi/smhi-mcp-server) explicitly describe themselves as fresh/rewritten specifically because of the March 2026 API change — source: GitHub repos cited above, accessed: 2026-09-12, confidence: high, class: integration
- For geocoding a Swedish address/place name to lat/long for free, **OpenStreetMap's Nominatim** public API (`https://nominatim.openstreetmap.org/search?q=...&format=json`) is a standard free option, but its usage policy caps traffic at **1 request/second total**, requires a meaningful User-Agent, requires attribution, and explicitly discourages periodic/background bulk geocoding (recommends caching or self-hosting for anything beyond occasional lookups) — source: OSM Foundation, "Nominatim Usage Policy", https://operations.osmfoundation.org/policies/nominatim/, undated, accessed: 2026-09-12, confidence: high, class: integration; corroborated by OpenStreetMap Wiki, "Nominatim", https://wiki.openstreetmap.org/wiki/Nominatim, version noted 2025-10-29, accessed: 2026-09-12, confidence: high, class: integration
- For a Sweden-specific alternative, a small free/no-key geocoding tool exists that resolves Swedish postal codes and municipality names to coordinates (built on GeoNames/Lantmäteriet open data), self-reporting a 60 requests/minute-per-IP limit — source: mackan.eu, "Kommunkollen API", https://mackan.eu/tools/kommunkollen/readme.php, undated, accessed: 2026-09-12, confidence: low, class: integration (single small/unverified publisher; not independently corroborated)
- SMHI runs a continuous public forecast-verification program: forecasts issued for 08:00 and 20:00 are compared against observations from ~180 Swedish weather stations, and a temperature (or wind) forecast is counted "correct" if it is within ±2°C (or ±2 m/s); results are published by county and month — source: SMHI, "Uppföljning av prognoser", https://www.smhi.se/data/temperatur-och-vind/temperatur/uppfoljning-av-prognoser, published: 2025-02-05 (updated 2025-09-23), accessed: 2026-09-12, confidence: high, class: accuracy — but note this program evaluates SMHI's forecasts in isolation (no independent second-source pass/fail rate confirming the exact ±2°C hit-rate numbers) and does not break out overnight/minimum-temperature performance specifically.
- Two independent Swedish university theses found only small, often statistically insignificant differences between SMHI's short-range (0–24h) temperature forecasts and competing services (Norway's met.no, and Yr) at Swedish stations, with met.no showing a slight edge for some stations/months in one study — source: Uppsala University (DiVA), "Comparison of Short-Range Temperature Forecasts from SMHI and the Norwegian Meteorological Institute", http://urn.kb.se/resolve?urn=urn%3Anbn%3Ase%3Auu%3Adiva-383449, undated (study covers Feb–May 2018 data), accessed: 2026-09-12, confidence: low, class: accuracy; and uppsatser.se thesis abstract, "Jämförelse av SMHI:s och YR:s 24-timmarsprognoser för temperatur och vindhastighet", https://www.uppsatser.se/uppsats/294a409bb4/, undated, accessed: 2026-09-12, confidence: low, class: accuracy. **Caveat: both studies evaluate general 2m/24h temperature forecasts, not specifically overnight minimum temperatures, and both predate the March 2026 SNOW1gv1 model/platform change, so they may not reflect the current forecast product.**

## Leads

- The March 2026 PMP3gv2 → SNOW1gv1 migration is very recent and is the single most important fact for anyone building against SMHI right now: any blog post, Stack Overflow answer, tutorial, or code sample dated before ~September 2025 almost certainly references the now-dead `pmp3g` endpoint and parameter names (`t`, `ws`, `Wsymb2`, nested `parameters[]`/`validTime`). A future assistant should treat pre-2026 SMHI integration write-ups as likely stale and verify against the current `snow1g` docs (https://opendata.smhi.se/metfcst/snow1gv1 and .../parameters) before trusting field names.
- SMHI also publishes a separate **Mesan2gv2** "meteorological analysis" API (recent gridded observations/nowcast, not a forecast) and a **fire risk** (Canadian FWI) product and official **weather warnings** API, per the LittleAndi/smhi-mcp-server feature list — potentially useful supplementary signals for a frost-alert tool (e.g. cross-checking with the analysis product, or warnings feed) but not evaluated here.
- The academic thesis comparisons (SMHI vs. met.no, SMHI vs. Yr) suggest it could be worth a future research pass specifically comparing SMHI vs. Yr/met.no for the frost-alert use case, since Nordic neighbor services are apparently comparable or occasionally more accurate for temperature — this could be a fallback/cross-check candidate rather than a replacement.
- Several community client libraries (thejoltjoker/smhi-snow, LittleAndi/smhi-mcp-server) were built/rewritten within days-to-weeks of the SNOW1gv1 cutover and could be useful integration references, but as brand-new (undated, low-star-history-unknown) repos they haven't accumulated much of a track record yet — worth a freshness check before depending on one.
- I could not verify official documentation content for https://opendata.smhi.se/metfcst/snow1gv1 or the parameters page directly — the fetch tool only returned client-side JS/theme bootstrap code (the docs site appears to be a JS-rendered Docusaurus app that didn't render statically for the fetcher). All SNOW1gv1 structural/behavioral claims here come from secondary developer sources (GitHub issues, forum posts, README files) that quote or link the official docs, not from reading the official docs' rendered content directly. A future pass with a JS-capable browser fetch could confirm these details straight from SMHI.
