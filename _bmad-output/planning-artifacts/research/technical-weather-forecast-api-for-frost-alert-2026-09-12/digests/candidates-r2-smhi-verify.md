# SMHI Forecast API — Deprecation/Migration Verification (R2)

Mission: independently verify the claim that SMHI retired its pmp3g meteorological
forecast API around March 31, 2026, replacing it with SNOW1gv1, breaking
third-party integrations. All items below were retrieved this session
(2026-09-12).

## Claims

- SMHI officially retired the PMP3gv2 forecast API on March 31, 2026, replacing it with a new API named SNOW1gv1 (SMHI also retired the Mesan2gv1 analysis API the same day, replaced by Mesan2gv2) — source: SMHI (official), "API för PMP3 avvecklas 31 mars", https://www.smhi.se/data/om-smhis-data/uppdateringar-oppna-data/uppdateringar-i-smhis-oppna-data/2026-03-16-api-for-pmp3-avvecklas-31-mars, published: 2026-03-16, accessed: 2026-09-12, confidence: high, class: integration, **status: verified**
- SMHI pre-announced the new SNOW1gv1/Mesan2gv2 APIs on 2025-09-12, giving roughly a 6.5-month transition window before retiring the old pmp3g/Mesan2gv1 endpoints on 2026-03-31 — source: SMHI (official), "Nya API:er för meteorologiska prognoser och analyser", https://www.smhi.se/data/om-smhis-data/uppdateringar-oppna-data/uppdateringar-i-smhis-oppna-data/2025-09-12-nya-apier-for-meteorologiska-prognoser-och-analyser, published: 2025-09-12 (updated 2026-02-04), accessed: 2026-09-12, confidence: high, class: reliability
- The retirement broke third-party integrations that hadn't migrated: (a) Home Assistant's built-in SMHI weather integration stopped updating and logged failed requests to the old `category/pmp3g/version/2` endpoint starting the morning of March 31, 2026, requiring a library patch to move to SNOW1gv1/Mesan2gv2 — source: GitHub (home-assistant/core), Issue #166935 "SMHI integration failing: Provider deprecated pmp3g API on March 31, 2026", https://github.com/home-assistant/core/issues/166935, published: 2026-03-31, accessed: 2026-09-12, confidence: high, class: integration, **status: verified**
- Independently, MagicMirror²'s SMHI weather provider module was also confirmed broken the same day, with the old endpoint returning HTTP 404 and the maintainers publishing the exact URL/field-mapping changes needed to migrate to SNOW1gv1 — source: GitHub (MagicMirrorOrg/MagicMirror), Issue #4081 "SMHI weather provider broken — PMP3gv2 API returns 404 since March 31, 2026", https://github.com/MagicMirrorOrg/MagicMirror/issues/4081, published: 2026-03-31, accessed: 2026-09-12, confidence: high, class: integration, **status: verified**
- The current, correct point-forecast endpoint is SNOW1gv1, e.g. `https://opendata-download-metfcst.smhi.se/api/category/snow1g/version/1/geotype/point/lon/{lon}/lat/{lat}/data.json`, with official docs at https://opendata.smhi.se/metfcst/snow1gv1 and parameter reference at https://opendata.smhi.se/metfcst/snow1gv1/parameters. Response shape changed materially from pmp3g (flat `data.{parameter}` object keyed by name, e.g. `air_temperature`, `wind_speed`, `symbol_code`, vs. old `parameters[].name/values`; `time` replaces `validTime`; coordinates are flat `[lon, lat]` not nested) — source: cross-referenced from GitHub (MagicMirrorOrg/MagicMirror) Issue #4081 (which links the official SMHI docs and shows working curl output), https://github.com/MagicMirrorOrg/MagicMirror/issues/4081, published: 2026-03-31, accessed: 2026-09-12, confidence: medium (the SMHI docs page itself is a JS-rendered SPA that did not return readable content via plain fetch this session — see Could not find), class: integration
- SMHI does not publish a fixed numeric SLA/version-support duration, but its FAQ states a standard advance-notice policy: minor changes to existing download services are announced ~3 months ahead, and larger/breaking changes ~6 months ahead, via the "Uppdateringar öppna data" page and RSS feed — source: SMHI (official) FAQ, "Frågor och svar", https://www.smhi.se/data/om-smhis-data/fragor-och-svar, accessed: 2026-09-12 (undated page, no publish date shown), confidence: medium, class: reliability
- This stated ~6-month notice policy is consistent with the observed pmp3g case (announced 2025-09-12, retired 2026-03-31, ≈6.5 months), suggesting the deprecation followed SMHI's own documented practice rather than being an abrupt/unannounced break — source: derived by cross-referencing the two SMHI announcement pages above, accessed: 2026-09-12, confidence: medium, class: reliability
- SMHI's current official usage guidelines (no numeric rate limit published) require: use only documented/cataloged APIs, avoid mass-downloading (e.g. pulling forecasts for many locations at once) or re-fetching identical data, respect cache lifetimes given in the dataset metadata, and accept shared/variable bandwidth; SMHI reserves the right to run maintenance windows and to block individual IPs or cut off service in cases of clear abuse — source: SMHI (official), "Villkor för användning av SMHIs öppna data", https://www.smhi.se/data/om-smhis-data/villkor-for-anvandning, published: 2024-12-17 (updated 2026-06-15), accessed: 2026-09-12, confidence: high, class: reliability

## Leads

- A web-search synthesis (not independently fetched/confirmed this session) suggested Mesan2gv2 (the analysis API, not the forecast API used for frost alerting) may already be scheduled for its own retirement around 2026-11-01, replaced by "Mesan2gv3." If true, this reinforces that SMHI's newer APIs are iterated on a similar ~6-month generational cadence and a frost-alert integration should not assume SNOW1gv1 is permanent. Worth a direct check of the SMHI "Uppdateringar öppna data" index (https://www.smhi.se/data/om-smhis-data/uppdateringar-oppna-data) before committing to SMHI long-term.
- SMHI's Open Data Portal (https://opendata.smhi.se) appears to be a JS-rendered (Docusaurus-style) SPA; scripted/plain HTTP fetches return only boilerplate/analytics JS rather than the documentation body. Any automation that wants to programmatically re-verify SMHI's docs (e.g. a CI check before deploying the frost-alert integration) will need a JS-capable fetch or should rely on the human-readable smhi.se announcement pages instead, which are plain HTML and did render correctly.
- The `pysmhi` Python library (referenced in the Home Assistant issue thread, https://github.com/gjohansson-ST/pysmhi) was patched to support SNOW1gv1 via PR #291 — worth checking as a ready-made, actively-maintained client rather than hand-rolling SNOW1gv1 parsing for the frost-alert automation.

## Could not find

- Could not retrieve readable content from SMHI's own SNOW1gv1 API documentation/parameter-reference pages (https://opendata.smhi.se/metfcst/snow1gv1 and .../parameters) directly — the fetch only returned client-side JS/analytics bootstrap code, not the rendered documentation body. The endpoint URL, field names, and structure were confirmed instead via the MagicMirror GitHub issue, which itself links to and quotes those same SMHI docs pages.
- Could not find an explicit, single SMHI statement giving a hard version-support/LTS commitment (e.g. "SNOW1gv1 will be supported for N years"). The only stability commitment found is the general advance-notice policy (~3 months minor / ~6 months major changes) in SMHI's FAQ — there is no SMHI document promising a minimum lifetime for any given API version.
- Could not independently confirm the "Mesan2gv2 retiring 2026-11-01 / replaced by Mesan2gv3" lead above with a direct source fetch this session (only surfaced as an unlinked point in a search-engine synthesis) — flagged as a lead, not a verified claim.
