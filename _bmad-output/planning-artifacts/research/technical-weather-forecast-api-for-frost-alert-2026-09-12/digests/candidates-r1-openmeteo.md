# Candidate Digest: Open-Meteo

Researched for: personal frost-alert automation (primary test case: Sweden), overnight low-temperature warnings for outdoor plants.

## Claims

**Pricing / rate limits (Q1)**

- Open-Meteo's Free/Open-Access API requires no API key, sign-up, or credit card, and is limited to non-commercial use — source: Open-Meteo homepage ("Free Open-Source Weather API"), https://open-meteo.com/, published: undated, accessed: 2026-09-12, confidence: high, class: pricing
- Free-tier limits are 600 calls/minute, 5,000 calls/hour, 10,000 calls/day, and 300,000 calls/month, applied per IP address — source: Open-Meteo Terms of Use, https://open-meteo.com/en/terms, published: undated, accessed: 2026-09-12, confidence: high, class: pricing (corroborated by Open-Meteo Pricing page, https://open-meteo.com/en/pricing, same access date, and by the Open-Meteo founder's comment on Hacker News, https://news.ycombinator.com/item?id=46589849, undated)
- The free tier carries "no uptime guarantee"; paid tiers (API Standard/Professional/Enterprise) add commercial-use rights, a dedicated `customer-api.open-meteo.com` endpoint with an API key, higher/unlimited rate limits, and a 99.9% uptime target — source: Open-Meteo Pricing page, https://open-meteo.com/en/pricing, published: undated, accessed: 2026-09-12, confidence: high, class: pricing
- Data is licensed CC BY 4.0 (attribution + link to licence required for any use, including redistribution); server source code is AGPLv3 on GitHub — source: Open-Meteo Licence page, https://open-meteo.com/en/licence, published: undated, accessed: 2026-09-12, confidence: high, class: pricing
- Open-Meteo's founder states the free tier is "cross-financed by commercial customers" and there is "no external funding, VCs, or whatsoever," with intent "to continue running the free API service as is" — source: Hacker News comment by Open-Meteo's creator, https://news.ycombinator.com/item?id=46589849, published: undated, accessed: 2026-09-12, confidence: medium (self-reported, single source, not independently verifiable), class: reliability
- Terms explicitly reserve the right to modify usage terms at any time, with changes tracked publicly on GitHub — source: Open-Meteo Terms of Use, https://open-meteo.com/en/terms, published: undated, accessed: 2026-09-12, confidence: high, class: pricing

**Forecast horizon, resolution, and models (Q2)**

- The `/v1/forecast` endpoint provides hourly data for 7 days by default, extendable up to 16 days via `forecast_days`; 15-minutely data is also available (interpolated outside Central Europe/North America) — source: Open-Meteo API Docs, https://open-meteo.com/en/docs, published: undated, accessed: 2026-09-12, confidence: high, class: coverage
- Open-Meteo blends 30+ national weather-service models (ECMWF IFS/AIFS, DWD ICON, NOAA GFS/HRRR, Météo-France ARPEGE/AROME, UK Met Office UKMO, JMA, KMA, GEM, and regional models) and auto-selects the best available model per location via a "best_match" default; individual models can be selected with the `models=` parameter — source: Open-Meteo API Docs, https://open-meteo.com/en/docs, published: undated, accessed: 2026-09-12, confidence: high, class: coverage
- Open-Meteo's data-sources table lists "MET Nordic" (provider: MET Norway) as an ingested model with 1 km resolution and a 2.5-day forecast length, updated hourly, alongside DWD ICON (2–11 km, 7.5-day horizon, updated every 3h) and ECMWF IFS/AIFS (9–25 km, 15-day horizon, updated every 6h) — source: Open-Meteo API Docs, https://open-meteo.com/en/docs, published: undated, accessed: 2026-09-12, confidence: high, class: coverage. Note: this confirms Nordic-specific high-resolution coverage exists in the blend, but the exact `models=` query value for MET Nordic was not confirmed in the fetched page (the visible model-selector list was DWD/ECMWF/NOAA/JMA/KMA/GEM/CMA/BOM only — see "Could not find").

**Overnight-low / minimum-temperature accuracy (Q3)**

- Open-Meteo publishes a "Previous Runs API" that exposes forecasts at fixed lead-time offsets (1–7 days out) so developers can compute their own MAE/RMSE/bias against observations or reanalysis; most models archived from January 2024 — source: Open-Meteo Previous Runs API docs, https://open-meteo.com/en/docs/previous-runs-api, published: undated, accessed: 2026-09-12, confidence: high, class: accuracy
- A third-party open-source tool, "VeriSky Scoreboard," scores Open-Meteo-sourced models (plus a few commercial APIs for preset cities) on temperature/rain/wind accuracy over a rolling 30-day window; for its New York preset, DWD ICON scored 66/100 overall and 84/100 on the temperature sub-score, while ECMWF AIFS and NOAA GFS scored in the low-70s — source: VeriSky Scoreboard GitHub repo, https://github.com/NickLeenders/verisky-scoreboard, and live scoreboard, https://nickleenders.github.io/verisky-scoreboard/?city=newyork, published: undated (repo active), accessed: 2026-09-12, confidence: medium, class: accuracy. Caveat stated by the tool itself: models are verified against Open-Meteo's own "best_match" analysis (a model reconstruction of observed weather), not independent station observations — so this is model-vs-model skill, not ground-truth accuracy.
- A second independent tool, "MeteoRight," is built specifically to compute MAE/RMSE/bias and lead-time-degradation curves from Open-Meteo's previous-runs/historical-forecast data — source: MeteoRight GitHub repo, https://github.com/Mumrah213/MeteoRight, published: undated, accessed: 2026-09-12, confidence: medium, class: accuracy (describes methodology; no published Sweden/Nordic-specific results found in this repo's description).

**Location input / geocoding (Q4)**

- The core forecast API takes only WGS84 latitude/longitude (comma-separated for multiple locations); no city-name or postal-code parameter exists on `/v1/forecast` itself — source: Open-Meteo API Docs, https://open-meteo.com/en/docs, published: undated, accessed: 2026-09-12, confidence: high, class: integration
- Open-Meteo offers a free, keyless companion Geocoding API (`https://geocoding-api.open-meteo.com/v1/search?name=...`) that resolves city names or postal codes to latitude/longitude, elevation, timezone, country code, and admin-area names, supporting up to 100 results per query and language/country filters — source: Open-Meteo Geocoding API docs, https://open-meteo.com/en/docs/geocoding-api, published: undated, accessed: 2026-09-12, confidence: high, class: integration (corroborated by the open-meteo/geocoding-api GitHub repo, https://github.com/open-meteo/geocoding-api/, undated, same access date, which states "Open-Meteo APIs are free for open-source developer and non-commercial use... we ask for fair use.")

**Integration ease (Q5)**

- All Open-Meteo APIs use plain HTTP GET with query parameters, return JSON by default, require no authentication for non-commercial use, and share consistent variable names/units across endpoints — source: Open-Meteo homepage, https://open-meteo.com/, published: undated, accessed: 2026-09-12, confidence: high, class: integration
- Official client SDKs exist for Python (`openmeteo-requests` on PyPI, maintained by Open-Meteo's founder Patrick Zippenfenig) and TypeScript/JavaScript (`openmeteo` on npm, ~42,000 weekly downloads); both use a FlatBuffers binary schema (from the `open-meteo/sdk` repo) for efficient large time-series transfer as an alternative to JSON — source: PyPI `openmeteo-requests` page, https://pypi.org/project/openmeteo-requests/, and npm `openmeteo` page, https://www.npmjs.com/package/openmeteo, published: undated, accessed: 2026-09-12, confidence: high, class: integration
- The `open-meteo/sdk` GitHub repo (schema source for the official SDKs) had 58 releases, latest v1.26.0 pushed 2026-03-21, with 20 contributors and active CI — source: GitHub `open-meteo/sdk` repository page, https://github.com/open-meteo/sdk/, published: 2026-03-21 (latest release), accessed: 2026-09-12, confidence: high, class: integration

**Reliability / sustainability (Q6)**

- The main API repository (`open-meteo/open-meteo`) has multiple documented 502 Bad Gateway outage reports on GitHub Issues in 2026, including a multi-hour outage attributed to a traffic spike/possible DDoS (issue #1801), a separate multi-hour 502/504 outage requiring a server migration (issue #1870), and a "high number of 502 errors" issue closed 2026-05-23 that the maintainer attributed to users running cron jobs every 15 minutes hitting free-tier limits — source: GitHub issues open-meteo/open-meteo #1801, #1870, #1866, https://github.com/open-meteo/open-meteo/issues/1801, /1870, /1866, published: 2026 (issue #1866 explicitly dated 2026-05-23), accessed: 2026-09-12, confidence: high, class: reliability
- The founder (Patrick Zippenfenig) actively and quickly responds to outage reports, temporarily tightens rate limits to stabilize service during incidents, and explicitly recommends the paid `customer-api.open-meteo.com` tier for reliability-sensitive use — source: GitHub issue open-meteo/open-meteo #1801, https://github.com/open-meteo/open-meteo/issues/1801, published: 2026, accessed: 2026-09-12, confidence: high, class: reliability
- Open-Meteo publishes a public status page with live status and incident history at status.open-meteo.com — source: Open-Meteo Pricing page, https://open-meteo.com/en/pricing, published: undated, accessed: 2026-09-12, confidence: medium (page reference confirmed; live incident history itself not independently fetched this session), class: reliability
- The main repository has roughly 6,000 GitHub stars and is written primarily in Swift — source: GitHub issue page metadata for open-meteo/open-meteo #1866, https://github.com/open-meteo/open-meteo/issues/1866, published: 2026-05-23, accessed: 2026-09-12, confidence: medium, class: reliability
- Terms of use explicitly disclaim any guarantee of accuracy, completeness, or uninterrupted availability of the free service, and cap total liability at subscription fees paid in the prior 12 months — source: Open-Meteo Terms of Use, https://open-meteo.com/en/terms, published: undated, accessed: 2026-09-12, confidence: high, class: reliability

## Leads

- Confirm the exact `models=` API value needed to force MET Nordic (MET Norway) selection for Swedish coordinates, versus relying on `best_match` to pick it automatically — the docs page's visible model dropdown list did not clearly include a MET Nordic entry even though the Data Sources table lists it as an ingested model.
- A stray, unsourced Hacker News comment claimed a credit card is now required "even for the free access" — this directly contradicts the official homepage's "No API key, no sign-up, no credit card" claim. Likely refers to the commercial/customer tier or a since-changed/misremembered detail; treat the official docs as authoritative but worth a quick re-check against the live sign-up flow before committing.
- Look for a Nordic- or Sweden-specific accuracy comparison (VeriSky and MeteoRight both default to non-European test cities/generic methodology); no Sweden-specific overnight-low verification numbers were located this session.
- Check status.open-meteo.com directly for a longer-term uptime percentage/incident frequency rather than relying only on GitHub issue reports.
- Review the Open-Meteo AGPLv3 self-hosting option as a fallback if free-tier reliability becomes a problem for an unattended hobby automation (mentioned in the HN thread as a supported use case).
