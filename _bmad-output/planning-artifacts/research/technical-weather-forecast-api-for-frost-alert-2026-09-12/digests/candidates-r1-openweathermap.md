# Candidate Digest: OpenWeatherMap

Research pass for frost-alert automation (Sweden primary test case). All claims retrieved this session (2026-09-12).

## Claims

- OpenWeatherMap's "Free Weather API access" plan (no credit card required to sign up) includes: Current Weather API, 3-hour Forecast for 5 days, Air Pollution API, Weather Maps (15 layers), and the Geocoding API, at 60 calls/minute and 1,000,000 calls/month — source: OpenWeatherMap, "Self-Service API Pricing" (openweathermap.org/price), URL: https://openweathermap.org/price.md, published: undated (live pricing page), accessed: 2026-09-12, confidence: high, class: pricing
- The free-plan rate limit is 60 API calls/minute; exceeding it returns HTTP 429 — source: OpenWeather, "Frequently Asked Questions" (docs.openweather.co.uk/faq), published: undated, accessed: 2026-09-12, confidence: high, class: pricing
- The 3-hour-step / 5-day forecast endpoint (`data/2.5/forecast`) accepts lat/lon, city name, or city ID and is part of the no-card free tier — source: OpenWeatherMap, "5 Day / 3 Hour Forecast" docs (openweathermap.org/api/forecast5), URL: https://openweathermap.org/api/forecast5.md, published: undated, accessed: 2026-09-12, confidence: high, class: coverage
- Maximum free hourly-resolution horizon under the no-card free tier is 5 days at 3-hour steps (i.e., 8 data points/day, not true hourly); true hourly resolution (48h) and daily-8-day summaries require the separate "One Call by Call" (One Call API 3.0) subscription — source: OpenWeatherMap price.md and OpenWeather FAQ (docs.openweather.co.uk/faq), accessed: 2026-09-12, confidence: high, class: coverage
- One Call API 3.0 is NOT part of the no-card free plan; it requires a separate "One Call by Call" subscription that mandates entering credit card details at signup, even though it includes 1,000 free calls/day (default cap is set to 2,000 calls/day, which can be lowered to 1,000 in billing settings to avoid any charge) — source: OpenWeather, "Frequently Asked Questions" (old.openweathermap.org/faq), published: undated, accessed: 2026-09-12, confidence: high, class: pricing
- A community report describes this credit-card requirement for One Call 3.0 as an "upstream change by OpenWeatherMap" affecting all applications that adopted the API, confirming it is a real friction point developers hit in practice (not just theoretical docs language) — source: Volumio Community forum, "[PLUGIN] Now Playing" thread, URL: https://community.volumio.com/t/plugin-now-playing/50318?page=46, published: undated (thread post), accessed: 2026-09-12, confidence: medium, class: reliability
- One Call API 3.0 (when subscribed) provides, per call: current weather, minute forecast for 1 hour, hourly forecast for 48 hours, daily forecast for 8 days, national weather alerts, and 4-days-ahead-by-timestamp historical/forecast data — source: OpenWeather, "Frequently Asked Questions" (docs.openweather.co.uk/faq), accessed: 2026-09-12, confidence: high, class: coverage
- OpenWeatherMap provides a Geocoding API (direct: name/zip→lat-lon; reverse: lat-lon→name) that is included in the free plan at the same 60 calls/min, 1,000,000 calls/month limits — so location can be specified by city name or postal/zip code (with country code) and resolved to lat/lon before calling forecast endpoints, rather than requiring the user to already know coordinates — source: OpenWeatherMap, "Geocoding API" docs (old.openweathermap.org/api/geocoding-api) and openweathermap.org/bbox-groupby-transfer, accessed: 2026-09-12, confidence: high, class: integration
- Direct geocoding endpoint format: `http://api.openweathermap.org/geo/1.0/direct?q={city name},{state code},{country code}&limit={limit}&appid={API key}`, returning up to 5 ranked results as JSON — source: OpenWeatherMap Geocoding API docs (old.openweathermap.org/api/geocoding-api), accessed: 2026-09-12, confidence: high, class: integration
- OpenWeather's own published accuracy metrics (self-reported, not independently audited) for its nowcast/NWP model, measured against unspecified "reliable" ground-truth sources over a two-month analysis window: Mean Absolute Error ≈ 0.5°C, RMSE < 2°C, "Reliability" (% of readings within ±2°C) between 90–100%, "Inaccuracy" (% of readings off by >5°C) ≈ 1% — source: OpenWeather, "Accuracy and quality of weather data" (Medium/openweathermap.medium.com and uk.phase.owm.io/accuracy-and-quality), published: undated, accessed: 2026-09-12, confidence: low (self-published, no independent verification, no Nordic/Sweden-specific or overnight-low-specific breakdown), class: accuracy
- No independent, station-verified accuracy benchmark for OpenWeatherMap (or its main free-tier competitors) at production scale was found; secondary comparison sites explicitly state OpenWeatherMap does not publish large-scale independent accuracy benchmarks — source: apiscout.dev, "OpenWeatherMap vs Weatherbit (2026)", URL: https://apiscout.dev/guides/openweathermap-vs-weatherbit-api-2026, published: 2026 (site dated for 2026), accessed: 2026-09-12, confidence: medium, class: accuracy
- A user report (US-based, not Nordic) on the openHAB community forum describes OpenWeatherMap forecasts running noticeably "too hot" versus the US National Weather Service, with other users in the same thread stating they stopped relying on any provider's forecasts (including OWM) due to general unpredictability — source: openHAB Community forum, "Openweathermap forecast accuracy" thread, URL: https://community.openhab.org/t/openweathermap-forecast-accuracy/164670, published: 2025-06-25, accessed: 2026-09-12, confidence: low (anecdotal, single non-Nordic case, ~15 months old), class: accuracy
- Response format for OpenWeatherMap's core weather and geocoding endpoints is JSON (with XML also offered for some legacy endpoints), authenticated via a simple `appid` API-key query parameter — source: OpenWeatherMap forecast5 and geocoding docs, accessed: 2026-09-12, confidence: high, class: integration

## Leads

- Could not confirm within budget whether OpenWeatherMap now markets a "One Call API 4.0" as a newer/renamed product superseding 3.0 (mentioned only in a secondary aggregator, apiscout.dev); worth verifying directly against openweathermap.org/api docs before committing to an integration target, since endpoint names/URLs may differ from 3.0.
- No historical pricing-change timeline (e.g., exact dates when the free "One Call 1.0/2.5" endpoints were deprecated or when the credit-card requirement was introduced for One Call 3.0) was retrieved this session — worth a follow-up search specifically for "OpenWeatherMap One Call 2.5 deprecation date" or the official changelog/blog to date-stamp the pricing-model history requested in Q1.
